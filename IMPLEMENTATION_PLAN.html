🔒 ZeroChat - Phase 1 (Live Chat Only)

Threat Model: State-level adversaries
User Profile: Journalists, activists, whistleblowers
Design: Anonymity over availability

⚠️ Phase 1 Limitations
  • Both users MUST be online - No offline messaging
  • No delivery guarantees
  • No persistent sessions
  • No direct P2P (relay-only WebRTC)
  • Connection failure preferred over metadata leakage

Dead-drop offline messaging planned for Phase 2

Architecture Decisions

Component Choice Rationale
Mixnet Self-hosted NYM Full control, no paid services
WebRTC RELAY-ONLY Prevents IP disclosure
ICE Relay candidates ONLY Host/srflx blocked
Keys Passphrase → Argon2id Keystore NOT trusted
Offline NOT IMPLEMENTED Phase 2 only

Technology Stack

Core

  • Language: Kotlin 1.9+
  • Min SDK: API 26
  • UI: Jetpack Compose
  • DI: Hilt

Anonymity

  • Mixnet: Self-hosted NYM
  • WebRTC: Relay-only mode
  • ICE: Blocked host/srflx

Crypto

  • Library: Lazysodium
  • KDF: Argon2id (512MB)
  • E2E: Session ratchet

Storage

  • DB: SQLCipher
  • Key: Passphrase-based
  • NO: Metadata, contacts

Key Security Properties

  • Unlinkability: NYM mixnet prevents traffic correlation
  • IP Protection: Relay-only WebRTC, oblivious TURN
  • Metadata Resistance: No queues, receipts, persistent state
  • Coercion Resistance: Duress passphrase destroys keys
  • Seizure Resistance: Passphrase required (NOT Keystore)
  • Live Only: Both users must be online (no offline messaging)
