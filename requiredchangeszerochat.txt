pub async fn run_churn_oracle(
    nym_stats: Arc<NymStats>,
    i2p_stats: Arc<I2pStats>,
    event_tx: mpsc::Sender<ChurnEvent>,
) {

        interval.tick().await;
        if nym_stats.consecutive_ack_failures() > 3

    }

3. Adaptive Cover-Traffic Scheduler (Rust core)
What the paper claims: When in S_hardened, the Nym cover-traffic Poisson rate drops from the full λ = 0.30 s⁻¹ to a dynamically computed minimum λ_min = ln(|S_t|) / 60, where |S_t| is the current Nym anonymity-set size. At the typical mainnet size of ~1,200 nodes, this gives λ_min ≈ 0.12 s⁻¹ — a 60% reduction.
Changes needed:
cover_traffic.rs — replace the hardcoded Poisson rate with an adaptive one:
rustconst LAMBDA_FULL: f64 = 0.30;       // used in S_rend
const DELTA_ANON_SECS: f64 = 60.0;   // deanonymization window

fn compute_lambda_min(anonymity_set_size: usize) -> f64 {
    (anonymity_set_size as f64).ln() / DELTA_ANON_SECS
}

// Called every time you schedule the next cover-traffic packet:
fn next_cover_packet_delay(state: &LifecycleState, set_size: usize) -> Duration {
    let lambda = match state {
        LifecycleState::Rendezvous => LAMBDA_FULL,
        LifecycleState::Hardened   => compute_lambda_min(set_size),
        _                          => 0.0,
    };
    // Poisson inter-arrival: exponential distribution
    let delay_secs = -((1.0 - rand::random::<f64>()).ln()) / lambda;
    Duration::from_secs_f64(delay_secs)
}

## Already in your sequential model (Document 1) — confirm these are actually built

These were in your original design but the paper claims them as measured facts. If they're not yet implemented, they need to be.

**Uniform packet padding (item 9 in Doc 1)** — the paper claims `D_KL ≈ 0.069` traffic indistinguishability. That number assumes packets are padded to uniform size. If you're not padding Sphinx frames to a fixed MTU before the obfs4 wrap, your actual KL-divergence will be higher.

```rust
// In nym_transport.rs, before wrapping:
const SPHINX_PADDED_SIZE: usize = 1452; // match your Nym MTU
fn pad_to_fixed(frame: &[u8]) -> [u8; SPHINX_PADDED_SIZE] {
    let mut out = [0u8; SPHINX_PADDED_SIZE];
    out[..frame.len()].copy_from_slice(frame);
    out
}
// Then: obfs4_wrapper.send_wrapped(socket, &pad_to_fixed(frame), dest)
```

**CPU load smoothing / gradual exploratory tunnel builds (item 5 in Doc 1)** — the paper claims the power fingerprint is "minimal." That requires i2pd's `exploratory.quantity` to be throttled. Add to your i2pd config:

```ini
exploratory.inbound.quantity=1
exploratory.outbound.quantity=1
# build them one at a time, not in parallel bursts
```

**Sphinx header pre-computation** — the paper claims entry latency of 7.1–9.8s across device tiers. That number requires Sphinx headers to be pre-computed on a background thread before the user taps Connect, so they're ready instantly. If you're computing them on-demand at session start, your latency numbers will be higher on low-end devices.

```rust
// Start this in onForeground(), before user taps Connect:
tokio::spawn(async move {
```
