ZeroChat: A Phased-Lifecycle Hybrid Transport
for Forensic-Hardened and Metadata-Minimized
Mobile Communication
Prabhneet Kaur1, Harshit Gulati1, Akshat Jain1, and Nipun Bansal1
Dept. of AI and Data Science, VIPS-Technical Campus, New Delhi 110034, India
harshit.gulati@vips.edu
Abstract. We present ZeroChat, a mobile communication architec-
ture that resolves the anonymitylatency initialization problem through
Phased-Lifecycle Transport (PLT). We are explicit: ZeroChat is an engi-
neered temporal decoupling of two existing protocols, not a new crypto-
graphic primitive. By bootstrapping over the Nym mixnet within 7.1±
0.43 s while concurrently initialising an I2P Garlic Tunnel, it achieves
91.2% entry-latency reduction with continuous GPA resistanceand a
measured bandwidth overhead of only 1.34× under adaptive protocol se-
lection (Section 8). Three prior gaps are closed: (1) obfs4 transport plug-
ging is implemented and measured, not deferred; (2) network-churn re-
silience is formally characterised with a Sfallback recovery path; (3) Trans-
port Lifecycle Isolation (TLI) delivers deterministic secret erasure within
50 ms, conrmed across 750 sessions. A 10,000-trial Monte Carlo simu-
lation conrms DKL ≈0.069 throughout migration.
Keywords: Metadata minimization · Mixnets · Garlic routing · Forensic
hardening · Rust FFI · obfs4 · DPI resistance · Network churn · Thermal
throttling

Introduction
Transport-layer metadata undermines mobile communication security [8]: even
under E2EE, peer identities, timing signatures, and packet-size distributions
remain accessible to GPAs [1]. High-entropy anonymity networks (Nym [2],
I2P [13]) provide GPA resistance but impose an initialization tax exceeding
80 s on mobile hardware, driving users toward less-protected alternatives.
What ZeroChat is and is not. ZeroChat does not introduce new cryptographic
primitives. It contributes a temporal decoupling architecture: perceived entry time
is decoupled from cold-start of the highest-entropy layer by running initialisation
concurrently with use. The initialization tax is deferred, not removed. This is en-
gineering workexactly the kind the applied security community needsclosing
the gap between cryptographic maturity and real-world deployment.

Three open problems closed in this paper. Prior work left three deployment
blockers unresolved; we close all three. (1) DPI resistance: Nym's distinc-
tive trac signature makes it trivially blockable by commodity ISP equipment.
We implement an obfs4 pluggable-transport wrapper [10] inside the Nym client
Rust layer (Section 6), measured to add only +1.2 ms median latency over-
head while rendering Nym ows statistically indistinguishable from HTTPS.
(2) Network-churn resilience: The Nym and I2P networks experience pe-
riodic churn events (node dropout, routing table instability). We add a formal
Sfallback state and a churn-detection oracle to the lifecycle automaton (Section 7),
ensuring graceful degradation without exposing users to an unprotected state.
(3) Bandwidth overhead: The naive dual-protocol overhead of 2.1× is unac-
ceptable for metered mobile data. Adaptive cover-trac scheduling reduces the
operational overhead to a measured 1.34× (Section 8).

Threat Model
Denition 1 (GPA). AGPA: observes ISP-level trac across f < 1/3 of Nym
mix layers [2]; performs statistical timing correlation; cannot inject or modify
packets.
Denition 2 (DPI Censor). ADPI: operates commodity DPI hardware at ISP
level; classies and drops ows by protocol ngerprint; cannot break transport-
layer encryption but can perform trac blocking.
Denition 3 (LFA). ALFA: physical device access after session end Tend; per-
forms cold-boot RAM dumps and JVM heap snapshots.
Denition 4 (Sybil Adversary). ASybil: deploys s malicious Nym nodes out
of N total (ρ = s/N); attempts deanonymization during Srend (Section 3).
Scope. ZeroChat does not claim resistance against: active injection attacks;
ASybil with ρ≥1/3; endpoint malware during active sessions. ADPI is mitigated
by the obfs4 layer (Section 6).
Security Property 1 (Forensic Amnesia). For all sessions terminated at
Tend: Pr[ALFA recovers key material] ≤εz ≈0, bounded by zeroize's overwrite
guarantee [12].

Related Work
Loopix [11] establishes Poisson-delay shuing as a GPA countermeasure at pro-
hibitive mobile-battery cost. Nym [2] extends this with incentivized relays. Sev-
eral systems [6] trade anonymity for latency without forensic guarantees. Hoang
et al. [4] formalise the JVM forensic-persistence risk; ZeroChat is the rst de-
ployed system implementing their native-language containment recommendation.
obfs4 [10] provides polymorphic DPI resistance for Tor; we adapt it to wrap
Nym's Sphinx trac. No prior system combines temporal transport layering,
DPI resistance, churn resilience, and forensic amnesia in a single mobile-native
deployment.

DPI Resistance via obfs4 Integration
6.1
Implementation
Commodity DPI hardware classies bare Nym/Sphinx framing within 35 pack-
ets by inter-packet timing and frame-length distribution, making obfs4 integra-
tion mandatory rather than optional. The obfs4 pluggable transport [10] uses
an Elligator2-encoded DH handshake to produce a byte stream computationally
indistinguishable from uniformly random data. We wrap all outbound Sphinx
frames in the Rust layer before they reach the Android socket; the ephemeral
handshake key is co-located in TLI and erased on terminate().

Network Churn Resilience
We dene a churn event as any of the following observable conditions:
 Nym: > 3 consecutive Sphinx ACK failures, or gateway RTT > 5× rolling
median (σrtt).
 I2P: tunnel build failure rate > 40% over a 30 s window, or NetDB reachable-
router count falls below 12.
The churn oracle runs as a background Tokio task in the Rust core, sampling at
2 Hz. On detection, it res a ChurnEvent to the lifecycle state machine, triggering
the Sfallback transition.
Denition 6 (Churn Recovery Bound). Let Tr = 90 s be the maximum re-
covery window. On entering Sfallback, ZeroChat: (a) buers outbound messages
in an in-memory queue (max 64 messages, oldest-drop); (b) attempts exponen-
tial backo reconnection to the aected network starting at 2 s; (c) on recovery,
replays the queue and transitions to Srend; (d) on timeout > Tr, terminates the
session via terminate() and noties the UI.
No unprotected state is reachable: Sfallback retains the surviving transport's pro-
tection throughout recovery. Table 4 shows measured recovery performance.

Adaptive Bandwidth Scheduling
The reported 2.1× overhead is peak cross-fade load, sustained for ≤τ =10 s. In
Srend, only Nym is active (I2P generates background bootstrap trac at 4.1±
0.8 kB/s). In Shard, I2P carries all message trac while Nym is throttled to λmin,
the lowest Poisson rate that preserves anonymity-set membership (Table 5).
In Shard, the Nym cover-trac rate is reduced to the minimum anonymous
rate λmin: the lowest Poisson rate at which the client remains indistinguishable
from active Loopix participants. We compute λmin from the current anonymity-
set size |St| using the bound from [11]:

Implementation
The i2pd router [5] links as a C++ shared library via bindgen. Cold-start opti-
misations: (a) eager i2pd startup at onForeground() saves 3.2±0.8 s; (b) AES-
256-GCM NetDB persistence saves 510 s; (c) LeaseSet pre-creation reduces
inbound connectivity from 38.4 s to 22.1 s; (d) 2-hop tunnels cut build time
from 39.7 s to 21.4 s; (e) thermal rate limiting at 82◦C prevents session collapse
on budget devices.

Perceived Entry Latency

11.2
Thermal Benchmarks
The Realme C21Y (SD 460) sustains 598 mW active and reaches 74◦C, within 6◦
of Android's throttle threshold. ZeroChat is not appropriate for sustained
high-frequency messaging on low-end hardware without thermal duty-
cycling. The thermal rate-limiter at 82◦C extends sustainable session duration
from ≈18 min to ≈34 min.

Discussion and Conclusion
Scope and applicability. ZeroChat is the correct choice when all three hold: (1) a
GPA operates at ISP level; (2) DPI-based Nym blocking is active or likely; (3) the
user tolerates 1.34× bandwidth overhead. Signal is strictly better for content-
only threats; I2P with TLI suces for device-seizure-only threats; nation-state
environments should use I2P-only mode (disabling Srend).
